# sheet-practice：分譜跟奏練習

[English](README.md)

**這個 repo 不含任何樂譜**，樂譜要自己準備：去哪裡找、怎麼處理，見 [docs/SCORES.md](docs/SCORES.md)。

把分譜（PDF 或掃描圖片，例如第二小提琴分譜）丟進去，本機網頁就會：

1. 用光學樂譜辨識（OMR，[homr](https://github.com/liebharc/homr)）把樂譜轉成 MusicXML
2. 同一「作品」底下的多個分譜（Vn I / Vn II / Vla / Vc…）合併成多聲部總譜，用 [OpenSheetMusicDisplay](https://opensheetmusicdisplay.org/) 顯示
3. 用弦樂音色播放，游標同步指到正在演奏的位置；可以只播其他聲部、把自己的聲部靜音或調小
4. 可調速度、播放／暫停、設定「起點 – 終點」小節反覆練習、拍點只在指定區段響
5. 自動檢查每小節「時值加總是否等於拍號」，把可能辨識錯誤的小節標紅；辨識錯的音符可以直接在頁面上修正，或下載 MusicXML 用 MuseScore 修完再上傳

一切都在本機執行，不需要網路（模型下載完成後）。

伺服器沒有帳號驗證，能連到的人都可以上傳、修改、刪除樂譜；不要開放到不信任的網路。

## 安裝

需要 Python 3.12 以上與 [uv](https://docs.astral.sh/uv/)。

```sh
cd sheet-practice
uv sync
uv run homr --init   # 第一次下載 OMR 模型（約數百 MB）
```

## 啟動

```sh
./run.sh
# 或
uv run uvicorn server:app --port 8777
```

瀏覽器開 <http://localhost:8777/>。

想先試用，可以產生兩份合成的示範作品（音符由程式產生，不是任何出版的樂譜）：

```sh
uv run python tests/fixtures/make_demo.py
```

譜預設放在 `data/`；要放到 repo 外面，設定 `SP_DATA_DIR`（例如 `SP_DATA_DIR=~/my-scores ./run.sh`）。

也可以先在命令列辨識，不經過網頁上傳（第 2、3 個參數是作品與聲部名稱）：

```sh
uv run python omr.py part.pdf "作品" "Violin II"
```

## 直接匯入現成的 MusicXML／MXL 總譜（建議）

有數位譜（.mxl 或 .musicxml，每個樂章一個檔）就不必掃描。下面這行會從總譜抽出弦樂五部
（Violin I／II、Viola、Cello、Contrabass），把各樂章接起來，並把只寫在總譜第一個聲部的速度標記複製過來：

```sh
uv run python import_parts.py "作品" mvt1.mxl mvt2.mxl mvt3.mxl mvt4.mxl
uv run python import_parts.py --list mvt1.mxl                      # 看總譜裡有哪些聲部
uv run python import_parts.py "作品" score.mxl --part "Violin 2=Violin II"   # 只抽指定聲部
uv run python import_parts.py "作品" score.mxl --rights "CC0-1.0" --source "https://…"   # 記錄授權與來源
```

聲部名稱不是英文（例如義大利文的 Violini II、Violoncelli I - II）或要加鋼琴時，用 `--part "總譜名稱（可用正規表示式）=顯示名稱"`：

```sh
uv run python import_parts.py "作品" mvt1.musicxml mvt2.musicxml mvt3.musicxml \
  --part "Violini I=Violin I" --part "Violini II=Violin II" --part "Viole.*=Viola" \
  --part "Violoncelli.*=Cello" --part "Contrabbassi=Contrabass" --part "Pianoforte=Piano"
```

顯示名稱裡有 Piano／Viola／Cello／Bass 會自動選對應音色。由 MIDI 轉出的 MusicXML（music21）音高正確、
拍數加總也對，但節奏常帶量化雜訊（大量連音、三十二分音符、無 type 的音符），看譜會比較亂，播放沒問題。

.mscz 要先用 MuseScore Studio 另存成 .mxl／.musicxml（或 `mscore -o out.musicxml in.mscz`）。
匯入的譜有速度標記時，速度滑桿是「原速的百分比」，畫面上會顯示目前小節的 ♩ 速度。

## 管樂／銅管縮成一個聲部（管弦樂曲）

練弦樂分譜時，完整的管樂總譜太多行；`reduce_orchestra.py` 把管樂與銅管的分部檔縮成**一份兩行譜表**
（像鋼琴譜，高音／低音以中央 C 分）的伴奏聲部，只當和聲背景用：

```sh
uv run python reduce_orchestra.py <作品資料夾>            # 讀 Winds/ 與 Brass/ → Reduction/
uv run python reduce_orchestra.py <作品資料夾> --check    # 只檢查來源檔的小節時值
uv run python import_parts.py "作品" <作品資料夾>/Reduction/*_Reduction.musicxml \
  --part "Winds & Brass=Winds & Brass"
```

做法是把每小節切成「有音開始或結束」的片段，每段把當下發聲的音疊成一個和弦，跨片段的音用連結線接起來；
移調樂器（單簧管、法國號…）會依 `<transpose>` 換成實際音高，和弦超過 `--max-notes`（預設 6）個音時
保留最低、最高與不重複的音高類別。每小節的長度以 `--reference`（預設同作品的 `Strings/`）為準，
所以不完整小節（弱起、樂章交界）會照原樣保留，播放的時間軸不會被拉長。

**來源品質要先確認**：`--check` 會列出「音符超出小節長度」的小節。這種檔案（常見於 MIDI 轉出的譜）
匯入後會讓該小節被拉長、各聲部對不齊；縮譜時這些音會被丟掉。聲部名稱裡有 wind／brass／horn 等字樣時，
播放會自動用簧風琴音色，和弦樂分得開。

## 使用方式

| 操作 | 方法 |
| --- | --- |
| 上傳分譜 | 「＋ 上傳分譜」，填作品名稱與聲部名稱；接受 PDF、PNG/JPG、MusicXML/MXL。PDF 每頁約 15–30 秒辨識，完成後自動載入 |
| 多聲部 | 同一作品名稱下的分譜自動合併成總譜（依「管理」裡的順序由上到下）。頂端「聲部」列：勾選 = 播放該聲部，點名稱 = 設為練習聲部；「練習聲部音量」可把自己的聲部調小或關掉 |
| 播放／暫停 | ▶ 按鈕或 **空白鍵**；■ 停止（停在目前位置，不跳回起點）；**Home** 回到起點（或區段起點） |
| 工具列 | 兩列：上排是播放（播放／停止、速度、目前樂章小節與 ♩、跳至），下排是聲部與「顯示」；其餘收在 **練習**（循環區段、拍點、預備拍、跳過長休止）與 **設定**（作品、音量、標準音、音色、立體聲、縮放、修正音符、原始掃描）兩個面板。工具列會**自動收起**：載入後顯示約 4 秒，滑鼠離開約 1.5 秒後往上收起，按播放立刻收起；滑鼠移到畫面上緣（或按上緣的小標籤、觸控點一下）就會出現，滑鼠在工具列上或游標在欄位裡時不會收。工具列是蓋在樂譜上的，收起／展開不會動到捲動位置。收起時右上角顯示**目前樂章、小節與第幾拍**。修正音符模式不會自動收起；要完全關掉自動收起，在瀏覽器主控台執行 `localStorage.toolbarAutoHide = "off"` 後重新整理 |
| 顯示方式 | 「顯示」選 **捲動**（預設）或 **翻頁**。捲動：樂譜是一條連續往下捲的長條，播放時游標所在的行保持在畫面上方約三分之一、平滑地往下捲（一行的最後一小節就開始往下一行移），快到底時自動在下面接上後面的樂譜，捲過很遠的部分會移除；和翻頁模式一樣不跨樂章：只在同一樂章內往下接，播到下一樂章時換成那個樂章（開頭標出樂章名稱）。播放中自己捲動（滾輪、拖捲軸、PageUp／PageDown）會暫停跟隨，按播放或跳小節（點小節、← / →、跳至、Home）恢復。翻頁：一次一頁，播到頁尾換頁。選擇記在瀏覽器裡 |
| 標準音 | 「A=」欄位設定 A4 頻率，預設 442 Hz（播放的音高整體微調） |
| 音色 | 弦樂（獨奏取樣，有抖音）／弦樂合奏（慢弦）／管風琴／簧風琴／純音（正弦＋泛音）。對和聲、校音準時建議用純音或風琴：音高穩定、沒有抖音、長音不會衰減 |
| 立體聲分佈 | 各聲部由左到右排開（Vn I 最左、Cb 最右），比較容易聽出自己的聲部和哪一部在對 |
| 調速度 | 速度滑桿是原速的百分比（20–150%），**+ / −** 鍵 ±5%，½ ¾ 原速快捷鈕；譜上有速度標記（含樂章／段落變速）就照譜，沒有則以 ♩=100 當原速。**每個樂章各自記住自己的練習速度**：滑桿顯示與調整的是游標所在樂章的速度 |
| 跳到某小節 | 「跳至」欄輸入小節號按 Enter：`12` = 本樂章第 12 小節（和印刷分譜一致）、`3:12` = 第 3 樂章第 12 小節、`#500` = 全曲第 500 小節；或直接點擊該小節；**← / →** 前後一小節；**PageUp / PageDown** 翻頁模式前後一頁（一頁 12–40 小節，聲部越多一頁越短，排版才快）、捲動模式捲一個畫面 |
| 樂章 | 用 `import_parts.py` 匯入多個樂章時，頂端會多一個「樂章」選單可以直接跳到樂章開頭；排版視窗不會跨樂章，標籤同時顯示樂章內的小節號（和印刷分譜一致）與全曲小節號 |
| 設定反覆區段 | **Shift+點擊** 小節 = 起點，**Alt+點擊** = 終點；或用 **[ / ]** 鍵以目前小節設定；也可直接在「小節 a – b」欄位輸入 |
| 開關循環 | 「循環」核取方塊或 **L** 鍵 |
| 拍點（節拍器） | 「拍點」選 關 / 全曲 / 指定區段；指定區段時按「＋區段」把目前循環區段（或目前小節）加入，例如只在切分音的伴奏段響拍點。**M** 鍵循環切換 |
| 預備拍 | 開始前先數一小節 |
| 跳過長休止 | 協奏曲練弦樂分譜時，所有非獨奏聲部（鋼琴以外）都休息超過 N 小節的段落（獨奏段）播放時直接跳過，只保留最後 M 小節當進入提示；被跳過的小節畫面上是灰色斜紋。沒有獨奏聲部的作品也適用（整個弦樂組長休止的段落） |
| 看原始掃描 | 勾「原始掃描」在右側顯示各聲部的 PDF 頁面，方便對照辨識結果 |
| 管理 | 改分譜的作品／聲部名稱、順序，重跑辨識，刪除 |

速度、區段、拍點區段、練習聲部、靜音、縮放等設定會自動存在作品底下，下次打開沿用。

## 拍數檢查與修正辨識錯誤

載入後會逐聲部逐小節檢查「音符時值加總」是否等於拍號應有的長度：

- **紅色小節**：時值不符（右上角標 `實際/應有` 拍數），很可能多認、漏認或時值認錯
- **粉紅小節**：完全空白
- 上方紅色列顯示數量，◀ ▶ 或 **E / Shift+E** 跳到上一個／下一個問題小節；「只看練習聲部」可以先只修自己的聲部

播放時，紅色小節會被拉長到「該小節最長聲部」的長度，各聲部在那一小節裡對不齊，修正後即恢復。

勾選「修正音符」進入修正模式，點選一個音符後：

| 按鍵 | 效果 |
| --- | --- |
| ↑ / ↓ | 升／降半音（自動依調號選擇升降記號） |
| Shift + ↑ / ↓ | 升／降八度 |
| W H Q E S T | 改成全／二分／四分／八分／十六分／三十二分音符 |
| `.` | 切換附點 |
| Delete | 改成休止符 |
| Shift + Delete | 整個刪除（OMR 多認出來的音符） |
| N | 休止符改成音符（B4，再用 ↑↓ 調整） |
| Shift + T | 設定此小節起的拍號（例如 `6/4`） |
| I | 在此小節後插入 N 個整小節休止 |
| X | 刪除此小節 |
| Cmd/Ctrl + Z | 復原 |
| Esc | 取消選取／離開修正模式 |

每次修改會自動拆回各聲部存到 `data/<分譜>/score.musicxml`，舊版本備份在 `backups/`。

### 自動對齊（實驗中）：`align.py`

`uv run python align.py <分譜 id> --dry` 會讀掃描頁每一行左邊印的小節號碼（RapidOCR），算出每一行「應該」有幾小節，
和 OMR 的結果比對：少的小節依譜表上方的多小節休止數字（例如 ▬10）展開，多的就合併被切開的小節，
無法判斷的行列在 `alignment.json`。但反覆記號（1./2. 房）、
樂章交界、OMR 把休止棒認成音符的行仍需手動處理；拿掉 `--dry` 才會真的改寫 `score.musicxml`（會先備份）。
有現成的 MusicXML 時就不需要這一步。

### 各聲部小節數對不齊

分譜裡的「多小節休止」（一個長方形加數字，例如 ■12）OMR 只會認成一小節，所以各聲部的小節總數常常不同，
合併後從第一個多小節休止開始就會錯位。目前的作法是手動對齊：

1. 用「原始掃描」對照，找到多小節休止的位置
2. 修正模式點該小節的休止符，按 **I**，填入「小節數 − 1」
3. 多認出來的小節用 **X** 刪
4. 用拍號變換（樂章交界）、排練記號核對各聲部是否已經對齊

錯誤很多（整段節奏、拍號、調號錯）時，比較有效率的作法是：
「⬇ MusicXML」下載整份多聲部譜 → 用 [MuseScore Studio](https://musescore.org/)（免費）修正 → 另存 MusicXML → 以同作品名稱、同聲部名稱重新上傳（上傳 MusicXML 不需要再跑辨識）。

## 載入與翻頁怎麼變快的

- **合併譜與時間軸都在伺服器快取**：分譜沒改就直接回傳（gzip 壓縮，1–2 MB 的傳輸量）。播放需要的時間軸（每個音的起點、音高、時值、速度）由 `timeline.py` 在伺服器算好，瀏覽器不必再載入整份譜分析。
- **第一次載入後在背景核對一次**：沒在播放時，瀏覽器用 OSMD 分析整份譜和伺服器的時間軸比對；一致就標記為已核對，不一致（通常是 MIDI 轉出、聲部溢出小節這類格式有問題的譜）就改用 OSMD 的版本並存回伺服器。所以游標位置和畫面永遠一致，之後再開也一樣快。這一步只在某份譜第一次打開（或改過之後）做一次，約 2–4 秒，只在空檔進行。
- **只排版一頁，而且前後頁先排好**：一頁的小節數依譜表數調整（五部弦樂約 24 小節）；目前這頁畫好後，空檔時先把後面幾頁和前一頁排好，翻頁就是切換顯示。播放中若下一頁還沒排好，會先把接下來 2.5 秒的聲音排進音訊佇列再排版，聲音不會斷。
- **捲動模式一次只排一小塊**：每塊試排的小節數依實測排版時間調整（目標約 60 ms，4–24 小節），只留下完整的行（最後一行可能不滿，藏起來，下一塊從那一行開始）；游標進入倒數第二塊時接下一塊，DOM 裡最多 6 塊。排版前一樣先把之後 2.5 秒的聲音排好。`localStorage.scrollChunk = "stretch"` 可改成「最後一行拉滿」的做法比較看看。

## 已知限制

- OMR 對掃描品質很敏感：斜、暗、密集的總譜辨識率會明顯下降；分譜（單一譜表）效果最好。
- 多小節休止、反覆記號、速度文字通常辨識不到；速度以 ♩=100 當「原速」。
- 每個分譜只保留第一個譜表。
- 播放用的是 General MIDI 弦樂取樣（WebAudioFont），是「音準／節奏參考」等級，不是擬真演奏；中提琴音色在極高音域缺樣本。
- 畫面一次只排版一頁（翻頁模式 12–40 小節，視譜表數而定）或幾小塊（捲動模式）；每頁／每塊都是從整份譜切出來的小段，開頭帶上當時的調號、拍號、譜號，所以每塊第一行都會重畫譜號與聲部名稱。
- 取樣音色本身有幾 cent 的走音（管風琴 +7、鋼琴 +10、慢弦 −2…），程式已依實測補正；純音則是數學上精確的 A=442。

## 專案結構

```
import_parts.py  從 MusicXML/MXL 總譜抽弦樂分譜、接樂章、複製速度標記，匯入成作品
reduce_orchestra.py  把管樂／銅管等分部縮成一份「鋼琴式」兩行譜表的伴奏聲部（弦樂練習用的和聲背景）
align.py         （實驗）用掃描頁的小節號碼與多小節休止數字對齊 OMR 結果
```
